# Регистрация участников корпоративных мероприятий

## 1. Контекст
Компания проводит конференции и обучающие сессии. Регистрация идёт через формы и таблицы, места заканчиваются неожиданно, на входе длинные очереди.

## 2. Цель
Сервис регистрации на мероприятия с лимитом мест, листом ожидания и отметкой прихода.

## 3. Функциональные требования
Система должна:
- вести мероприятия (название, дата и время начала, площадка, лимит мест);
- вести программу мероприятия — сессии с докладчиками и временем;
- регистрировать сотрудника на мероприятие (табельный номер — 6 цифр, email);
- при исчерпании мест ставить сотрудника в лист ожидания;
- при отмене регистрации автоматически переводить первого из листа ожидания в участники и уведомлять его;
- выдавать участнику код для входа;
- отмечать приход участника по коду на входе;
- показывать организатору статистику: зарегистрировано, в листе ожидания, пришло.

## 4. Ожидаемые компоненты
- мобильное приложение на Kotlin для участника (мои регистрации, код входа, уведомления);
- web-интерфейс организатора на Angular;
- backend на C#, PostgreSQL, события в Kafka;
- Docker, тестовые данные, тесты, CI/CD, документация.

## 5. Демонстрационный сценарий
1) организатор создаёт мероприятие на 2 места;
2) два сотрудника регистрируются, третий попадает в лист ожидания;
3) первый участник отменяет регистрацию;
4) третий сотрудник автоматически становится участником и получает уведомление;
5) на входе отмечается приход участника по коду;
6) организатор видит статистику.
